# **Rules and Regulations for Node.js MVP Backend**

### **1. Project Architecture**

* **Service-Based Architecture**: All core functionalities must be split into independent, reusable services (e.g., AuthService, UserService, PaymentService, NotificationService).
* **Layered Structure**:

  * `controllers/`: Handle HTTP requests and responses.
  * `services/`: Contain business logic, database queries, and external API integrations.
  * `models/`: Define database schema structures.
  * `middlewares/`: Authentication, validation, logging, and error handling.
  * `utils/`: Universal helpers like response formatting, error formatting, logging, and JWT utilities.
  * `routes/`: Define application endpoints and associate them with controllers.
  * `config/`: Environment variables, DB configuration, JWT secrets, and third-party API keys.
  * `validators/`: Request payload and query validations using a chosen validation library.

---

### **2. Validation Rules**

* All incoming requests must be validated for type, required fields, and constraints.
* Validation must be centralized using a middleware.
* Invalid payloads must return structured errors with:

  * Status code
  * Human-readable message
  * Invalid fields and reasons
* Optional: Implement dynamic validation schemas to reduce redundancy across endpoints.

---

### **3. Middleware Regulations**

* **Authentication Middleware**:

  * Every private route must verify JWT or session.
  * Expired or invalid tokens must trigger structured error responses.
* **Authorization Middleware**:

  * Role-based access control (RBAC) must be implemented.
  * Roles may include: Admin, Manager, Staff, Customer.
  * Middleware should verify user roles before executing controller logic.
* **Validation Middleware**:

  * Use validation middleware to prevent malformed requests from reaching services.
* **Error Handling Middleware**:

  * Centralized error handler to capture all exceptions.
  * Should log errors for auditing.
  * Provide generic response messages to users but detailed logs internally.
* **Logging Middleware**:

  * Log all incoming requests and responses.
  * Include timestamps, method, URL, and user ID if available.
* **Rate Limiting & Security**:

  * Limit requests per IP per route.
  * Include headers for CORS, CSP, and security best practices.

---

### **4. Utilities Regulations**

* **Response Utility**:

  * Standardized response structure for success and errors.
  * Include status code, message, data (for success), and errors (for failure).
* **Error Utility**:

  * Unified error format for all services.
  * Support custom error types: ValidationError, AuthenticationError, NotFoundError, etc.
* **Logging Utility**:

  * Structured logs for errors, info, and warnings.
  * Optionally integrate with services like Winston, Loggly, or Datadog.
* **JWT Utility**:

  * Issue and verify tokens.
  * Handle token expiration and revocation.
* **Async Utility / Universal Try-Catch**:

  * Wrap all async functions with a universal error-catching mechanism.
  * Prevent unhandled promise rejections from crashing the server.

---

### **5. Role-Based Access Control**

* **Package Selection**:

  * Use a proven RBAC package compatible with JS modules.
  * Must support hierarchical roles and team-based access if necessary.
  * Roles should be configurable via environment variables or database.
* **Roles and Permissions Rules**:

  * Define which roles can access which resources or endpoints.
  * Support role inheritance for modular permission management.
  * Enforcement occurs in middleware before hitting services.
* **Dynamic Role Decision (AI Pilot)**:

  * Implement a dynamic role resolution system that checks user attributes, team, and hierarchy to decide access.
  * Ensure default denial if role cannot be resolved.

---

### **6. Error Handling Regulations**

* All errors must be captured and formatted uniformly.
* API responses must not expose stack traces or sensitive information to users.
* Internal logs should capture stack traces for debugging.
* Validation, authentication, authorization, database, and service errors must all conform to the same response structure.
* Implement global exception handling to catch unhandled rejections or uncaught exceptions.

---

### **7. Security Rules**

* Always validate and sanitize user input.
* Passwords must be hashed securely using a strong hashing algorithm.
* API keys and sensitive credentials should only be stored in environment variables.
* Implement HTTPS in production and redirect all HTTP traffic.
* Apply rate limiting to prevent abuse.
* Use helmet or similar middleware to enforce security headers.

---

### **8. Database Rules**

* Use ORM or query builder for database interactions.
* Follow migration strategy to version database schemas.
* Always handle database errors and rollbacks to prevent inconsistent state.
* Separate read/write operations to optimize performance if necessary.

---

### **9. API Rules**

* RESTful API design.
* Consistent endpoint naming conventions (plural nouns for resources, versioned routes).
* Include pagination, filtering, and sorting for list endpoints.
* Include metadata in responses where necessary (e.g., total count for paginated responses).

---

### **10. Testing and MVP Compliance**

* All endpoints must have unit tests for service logic.
* Integration tests must cover middleware, controllers, and database interactions.
* MVP should include:

  * Authentication & registration
  * Role-based access control
  * One core resource CRUD
  * Error handling & logging
  * Validation for all input
* Ensure tests are automated and run on every CI/CD deployment.

---

### **11. Logging and Monitoring**

* Capture request/response logs.
* Track application metrics (errors, performance, latency).
* Integrate monitoring services for uptime alerts.

---

### **12. Deployment and Production Readiness**

* Use environment variables for configuration.
* Separate development, staging, and production configurations.
* Gracefully handle server shutdowns.
* Implement automatic restart and process management (e.g., PM2).
* Ensure proper CORS configuration for frontend access.
